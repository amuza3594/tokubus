# 徳島バス 系統実態調査アプリ

国の幹線補助金申請のために毎年実施している系統実態調査（後部座席での手書き調査）をデジタル化するPWA（Progressive Web App）です。
実際の「調査員入力シート」（Excel）の項目・出力形式に合わせています。

## 特徴

- **オフラインファースト**: 通信が不安定な区間でも入力・保存が可能。データは端末のIndexedDBにのみ保存され、サーバー通信は行いません。
- **スマホ/タブレットのブラウザで動作**: PWAとしてホーム画面に追加すればアプリのように起動できます（App Storeの審査不要）。
- **紙の調査シートと同じ流れ**:
  1. 基本情報（日付・乗務員氏名・調査員氏名・仕業番号・車号・路線名・系統番号・始発/終着停留所・時刻・系統キロ）を入力して調査開始
  2. 現在のバス停を指定し、乗車客ごとに性別・料金区分を記録（乗車No.は自動採番）
  3. 乗車中の客をタップして降車を記録（支払区分・区間料金、区間料金は後からまとめて入力も可）
  4. 調査終了後、記録内容を確認・修正し、「共有」からExcelファイルを送信
- **バス停マスタ（停車順・系統キロ）を保持し、左右スライド/ボタンでバス停を切り替え**: 系統番号がバス停マスタと一致すると、始発〜終着の停留所名・系統キロを手入力せず、順番に沿ってスワイプ操作で切り替えられます。マスタに無い系統番号は従来通り手入力にフォールバックします。
- **車内見取り図で乗車位置を見える化**: 乗車中の客を「リスト」だけでなく、簡易的なバス車内図（前方/中央/後方・着席/立席）の上に番号付きトークンとして表示。多客時にどの辺りに乗客が集中しているかを一目で確認でき、ドラッグで自由に位置を調整できます（乗車No.自体は自動採番のまま）。
- **降車時の基本区間運賃を自動入力**: GTFS運賃データ（乗車停留所→降車停留所の大人・現金の基本運賃）を内蔵し、降車記録画面を開くと自動で金額を入力します。属性による割引計算はせず常に大人普通運賃を入れるだけなので、実際と異なる場合はその場で自由に修正できます。データが無い区間（マスタ未収録の停留所ペアなど）は空欄のまま従来通り手入力します。
- **アプリ内からGTFSデータを更新可能**: ホーム画面右上の「⚙」からGTFSのzipファイルをそのままアップロードすると、開発者によるビルド・再デプロイなしで、その端末のバス停マスタ・系統キロ・運賃データがその場で更新されます（詳細は下記「バス停マスタ・運賃データの更新（GTFS）」参照）。

## データモデル

- `Survey`: 1系統1回の調査の基本情報
- `PassengerRecord`: 客番号（乗車No./降車No.）を軸に、乗車情報と降車情報を1レコードにまとめたもの（紙の調査シートで客番号が乗車欄・降車欄を紐づけている構造をそのまま再現）。車内見取り図上の位置（`mapX`/`mapY`、0〜1の正規化座標）も保持
- 料金区分（属性）: 高齢者・大人・学生・小児・大人身障・小児身障
- 支払区分: 現金・定期券・回数券・交通系IC・見せ券

## 開発

```bash
npm install
npm run dev             # 開発サーバー
npm run build           # 本番ビルド（tsc -b && vite build。PWA/Service Worker込み）
npm run preview         # ビルド結果をローカルで確認
npm run build:artifact  # 単一HTMLファイルにまとめたプレビュー用ビルド（dist-artifact/index.html）
```

`build:artifact` は動作確認用に、アプリ全体を外部リクエスト無しの1ファイルHTMLに固めるビルドです（Service Workerなし）。実運用のデプロイには通常の `build` を使ってください。

## 出力形式

調査ごと、または全調査（仕業番号ごとにシートを分けて）Excel（.xlsx）に出力できます。既存の「調査員入力シート」と同じ並び（基本情報＋停留所名／乗車No．／性別／料金区分／降車No．／支払区分／区間料金の1行1イベント形式、同一停留所は2行目以降を空欄）で出力するので、既存の集計フォーマットにそのまま流用できます。罫線・列幅（A列:16／B〜G列:11.40／H列:20.00）も指定通りに出力されます。列を調整したい場合は `src/utils/export.ts` を編集してください（Excel生成は [exceljs](https://github.com/exceljs/exceljs) を使用）。

「共有」ボタンは Web Share API（`navigator.share`）でExcelファイルを直接共有します。対応端末（Android Chrome、iOS Safari等）ではOS標準の共有シートが開き、コピー・ファイルに保存・メール・SNSなど、その端末にインストールされているアプリから選んで送信できます（宛先はアプリ側で入力）。非対応のブラウザでは自動的にファイルのダウンロードにフォールバックします。

## バス停マスタ・運賃データの更新（GTFS）

バス停マスタ（停車順・系統キロ）と運賃データは、どちらも徳島バスのGTFSフィードから自動生成しています。ダイヤ改正や運賃改定でGTFSデータが更新されたら、以下の2通りの方法で最新化できます。

### 方法1: アプリ内の設定画面からアップロード（開発者不要）

ホーム画面右上の「⚙」→「GTFSのzipファイルを選択して更新」から、GTFSのzipファイルをそのままアップロードするだけで更新できます。処理はすべてブラウザ内（クライアントサイド）で完結し、結果はその端末のIndexedDBに保存されます。ビルドやデプロイ、サーバーへの送信は一切不要です。

- アップロードしたデータは他の調査データと同様その端末にのみ保存されるため、複数の端末で使っている場合は端末ごとにアップロードが必要です。
- 「内蔵データに戻す」で、アップロード前の内蔵データにいつでも戻せます。
- 必要なファイル（下記7ファイル）が1つでも不足しているzipはエラーになり、データは更新されません。

### 方法2: 内蔵データ（アプリにビルド時から同梱される既定データ）を差し替える

将来的にアプリの初期状態からGTFSデータを最新にしておきたい場合は、開発者が以下を実行してコミットします（**1コマンドだけ**で両方最新化されます）。

```bash
# ダウンロードしたGTFSのzipファイルをそのまま渡す（data/gtfs/ に自動展開される）
node scripts/build-from-gtfs.mjs path/to/feed.zip

# あるいは、あらかじめ data/gtfs/ にファイルを展開済みなら引数なしでもOK
node scripts/build-from-gtfs.mjs
```

必要なGTFSファイル（`data/gtfs/` 直下に配置、または上記zipに同梱）:

- `stops.txt` / `routes.txt` / `trips.txt` / `stop_times.txt` / `shapes.txt`（バス停マスタ・系統キロ用）
- `fare_attributes.txt` / `fare_rules.txt`（運賃データ用）

このコマンドで `src/data/stopMaster.json` と `src/data/fareTable.json` が両方再生成されます。

**バス停マスタの生成ロジック**: 系統(`route_id`)・方向(`direction_id`)ごとに実際の便（トリップ）の停車順を集計し、最も出現頻度の高いパターンを採用します（同一系統で便によって経路が微妙に異なる場合への対処）。系統キロは `shapes.txt` の走行軌跡（緯度経度）から概算した距離です。GTFSの`direction_id`は往路・復路のどちらが0/1かを意味しないため、1方向のみの系統は「往路」、2方向ある系統は番号の小さい方を「往路」としていますが、実際とラベルが逆になっている可能性があります。基本情報入力画面の上下区分ボタンには実際の行き先（終着停留所名）を添えて表示するので、系統番号だけでなく行き先を見て選んでください。

**運賃データの生成ロジック**: GTFSの運賃は本来「路線(route_id)ごとの乗車停留所ゾーン→降車停留所ゾーン」で定義されていますが、バス停マスタ側は上下線で別の系統番号を割り当てる運用のため、系統番号を使わず「乗車停留所名→降車停留所名」のペアだけで運賃を引けるように変換しています。同じ停留所ペアで複数路線にまたがり運賃が一意に決まらない場合は、誤った金額を自動入力しないようそのペア自体を除外します（その場合は従来通り手入力）。

なお、このGTFSフィードに含まれない系統番号（対象外の路線など）はバス停マスタ・運賃データとも自動入力の対象外となり、従来通りすべて手入力になります。
